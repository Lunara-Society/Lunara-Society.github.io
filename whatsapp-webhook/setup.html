Getting WhatsApp talking to us

Meta wants a Callback URL and a Verify token. Here is where they come from, in the order they have to happen.

Our site can't answer this one. Meta verifies a webhook by sending a request carrying a hub.challenge value and demanding that exact value back. GitHub Pages hands out files — it cannot read a request and compose a reply, so no address on lunarasociety.com will ever pass.

A Cloudflare Worker can. That is all the code below is: a small program that answers Meta's question correctly, then listens for messages.

  1. 1

    Create the Worker

    In Cloudflare: Compute (Workers) → Create → Start with Hello World → Deploy. Name it lunara-whatsapp.

    Cloudflare gives you an address ending in .workers.dev. That address is the Callback URL — keep the tab open.

  2. 2

    Paste in the code

    Open Edit code, select everything already in the editor and delete it, then paste this and press Deploy.

  3. 3

    Add the two secrets

    In the Worker's Settings → Variables and Secrets, add both as type Secret.

    WHATSAPP_VERIFY_TOKEN
    The token below. The very same text also goes into Meta's Verify token box.
    WHATSAPP_APP_SECRET
    From Meta: App settings → Basic → App secret. This is what stops strangers sending us fake messages.

  4. 4

    Deploy a second time

    Press Deploy again now that the secrets exist. Skipping this is the commonest reason the next step fails — secrets only reach the running code on the deploy after you add them.

  5. 5

    Fill in Meta's two boxes

    Back on the Facebook developers screen: the .workers.dev address into Callback URL, the token into Verify token, then Verify and save.

  6. 6

    Subscribe to messages

    Still in Meta, under Webhook fields, subscribe to messages. Verifying and actually receiving are two separate switches — without this you get a green tick and total silence.

If something goes wrong

“The callback URL or verify token couldn't be validated.”

Nearly always one of two things: the token in Cloudflare doesn't match the token typed into Meta, or step 4 was skipped. Open the Worker's Logs tab and press Verify again — a mismatch writes Verification rejected, a missing secret writes WHATSAPP_VERIFY_TOKEN is not set.

It verified, but no messages arrive.

Either step 6 was missed, or the app is still unpublished. That orange warning on Meta's page is real: until you publish, it sends only test events from the dashboard button — no live messages, not even from your own number.

Until the app secret is set, the endpoint trusts anyone.

The Worker checks Meta's signature on every message once WHATSAPP_APP_SECRET exists, and writes a warning on every single request while it doesn't. Don't leave it half-done.

The token is generated in your browser and kept only there — it is never sent anywhere and is not stored in the repository. The Worker's source and its 16 tests live beside this page in whatsapp-webhook/.
